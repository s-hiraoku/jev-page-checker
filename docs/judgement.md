# 判定の原則

この製品は「知っているサイトを緑にする」ものではない。今見ているページについて、サイトの安全性と、記事があるときだけ本文の精査を、根拠として出す。ブロックも送信もしない。迷ったら要確認である。

## 禁止: 局所対応

あるサイトで望ましくない結果が出たとき、そのサイトだけ通るように合格線・指示・URL・ホストを曲げてはならない。それはそのサイトでしか機能せず、他のページでは同じ失敗が残る。問題の先送りである。

やってはいけないこと:

- 画面に出た noul / score / 確信度に `passAt` や `confidenceFloor` を合わせる
- 定義やコードに特定ホスト・特定著者・特定記事の固有名を書く
- パスが `/` だから、有名サイトだから、という例外分岐
- 「このサイトは記事ではない」「このサイトは信頼できる」をコードに埋め込む
- replay に実在サイトの点数を写して、それを合格条件にする

直すときは、聞いていること・構造の見分け・閾値の意味を、どの URL でも同じ規則になるように直す。

## やってよいこと

- サイト: 誰が責任者か、なりすましか、何のためのページか、隠し勧誘か
- 本文: 一本の文があるときだけ、根拠・事実と意見・出典・矛盾・断定
- 主本文が文字数上限で切れたときは、切れた先は判定していない。本文レーンは通過にしない。上限はどの URL でも同じ。サイト全体は見ない
- 一覧: リンク密度など、ページ構造で見る。ホストもパスも見ない
- 意見・分析は目的のラベルであり、それ自体は危険ではない
- Jev には意味だけを聞く。HTTPS・メタ・語数・リンク密度・本文が上限で切れたかはコードが見る
- noul の通過は 0.8、choice / score の確信度の床は 0.6。意味で決めた線であり、事例に合わせない
- 定義を変えたらリスト全体を再承認する。差分承認はしない
