# 本文分類とカテゴリ別チェックの設計案

状態: 実装済み（定義 v9）。分類の11種類と「分類保留」は合意済み。各項目の判定境界の具体例は継続して検証する。

## 目的と境界

今見ている**ページの主本文**を分類してから、その種類に合う質問で本文を確認する。ドメインや著者の知名度では分類しない。分類は「何を読むか」を決める情報であり、信頼性の点数ではない。サイトの安全性、本文の確認結果、本文の種類を別々に表示する。

既存の `pageKind` は記事か一覧かという構造、`site_purpose` は表示目的と安全性の質問である。この設計の本文分類とは別物として扱う。`site_purpose` は分類との重複をなくすため、「ページの目的が読者に分かるか」という問いに変更する。販売や創作という種類だけで警告しない。隠した勧誘やなりすましなどは従来どおり安全性の問いで扱う。

## 分類

| ID | 日本語 | English | 主な判断対象 |
| --- | --- | --- | --- |
| `reporting` | 報道・事実報告 | Reporting | 外部で起きた事実を伝える |
| `announcement` | 当事者の発表・告知 | First-party announcement | 当事者が自らの決定・予定を伝える |
| `explanation` | 解説・分析 | Explanation and analysis | 既存情報を整理し、意味や関係を解説する |
| `opinion` | 意見・提案 | Opinion and proposal | 立場や提案を論じる |
| `investigation` | 調査・検証 | Research and verification | 独自の方法で調べ、結果を示す |
| `guide` | 手順・ガイド | How-to guide | 読者が行う作業を説明する |
| `experience_review` | 体験・レビュー | Experience and review | 使用・体験に基づいて評価する |
| `sales` | 販売・勧誘 | Sales and persuasion | 購入、申込、寄付などの行動を促す |
| `reference` | 資料・参照 | Reference material | 定義、仕様、データなどを参照できる形で示す |
| `discussion` | 投稿・議論 | Posts and discussion | 複数の投稿、質問、回答、応答を扱う |
| `creative` | 創作・風刺 | Fiction and satire | 創作物、風刺、娯楽として読ませる |

「分類保留 / Classification needs review」は12番目のジャンルではなく判定状態。必要な本文が足りない、`unclear` が分類候補を上回る、または Jev の回答を読み取れないときに使う。一覧や本文がないページは「分類対象外 / No single body to classify」として区別する。

## 実行順序

1. 既存の抽出処理でページの形と主本文を得る。URL、ホスト名、知名度から本文の種類を推定しない。
2. 一本の本文があるとき、Jev の `choice` で主分類を選ぶ。選択肢には11分類と `unclear` を含める。ページタイトル、説明、主本文を入力する。根拠はページから切り出した文またはメタ情報を Jev に選ばせ、既存の引用元情報と一緒に記録する。
3. 本文の重要な部分が別の目的を持つときだけ、副分類を最大一つ選ぶ。単なる購入リンク、引用、例示は副分類にしない。主分類・副分類とその根拠を両方表示する。長文は既存の重複窓で全体を確認し、窓ごとの違いも記録する。
4. 主分類は、その回答の分布で最も高いカテゴリ（1 位）に決める。同点のときは、宣言された選択肢が同点の中のカテゴリならそれを使い、そうでなければ供給されたカテゴリ順で一つのカテゴリに割る。同点の相手は副分類に残さず、混在や分類保留にしない。確信度が 0.6 未満でも、1 位がカテゴリなら分類する。この床は合否の choice と score に使い、分類を未分類のままにしない。1 位が `unclear` だけで、どのカテゴリもそれに並ばないときは分類保留にする。副分類は別の質問の分布で `none` と主分類を上回る別目的が選ばれたときだけ一つ付ける。主分類と副分類の確信度は別の質問なので比較しない。窓が複数あるときは `unclear` も含めた 1 位の票数、次にその分布の合計、次に同じカテゴリ順で一つに決める。`unclear` が最多なら分類保留にする。本文の切れ残りがあるときは、分類・本文確認の完了を主張しない。
5. 分類が決まったら、その分類の評価軸だけを Jev に送る。重要な副分類があれば両方の評価軸を実行し、結果を分類別に表示する。分類保留ではカテゴリ専用の採点をせず、本文レーンを Review として理由を示す。
6. 一覧など一本の本文がないページでは本文質問を実行しない。サイトの安全性は別に確認する。

Jev の確信度は質問の振り分けと保留の判断にのみ使い、信頼性の点数にしない。分類の根拠文も信頼性の証明ではない。

## カテゴリ別の評価項目

サイト安全性は共通に確認し、本文はカテゴリごとに異なる項目で確認する。項目数をそろえるために質問を削ったり足したりしない。詳細な項目、項目数、参考資料は [`content-category-rubrics.md`](content-category-rubrics.md) にまとめた。

本文には全カテゴリ共通の採点軸を置かない。例えば「根拠」は報道では取材元、調査では方法とデータ、レビューでは実際に使った条件、ガイドでは再現できる操作として問う。各項目の Pass / Review / Alert / N/A の条件はカテゴリごとに定義する。

本文レーダーは項目数を制約にしない。項目はすべて一覧に表示し、チャートはカテゴリ内の関連項目を4〜6軸にまとめる。創作・風刺の本文は事実検証の対象外とし、誤認防止の4項目を確認する。重要な主張が本文にある場合は条件付き項目を追加する。カテゴリ間でレーダー形状や数値を比較しない。

## データと表示

レポートには分類の状態、分類 ID、Jev の回答と確信度、引用文、引用元（タイトル・説明・主本文など）、分割窓での不一致理由、実際に実行した質問 ID を保存する。古い履歴に分類情報がなければ「分類情報なし / Not classified in this earlier report」と表示し、閲覧時に再判定しない。

- 通常チェック: サイト・本文の判定の近くに「本文の種類 / Content type」を表示する。分類名の下に短い根拠文を一つ置く。保留、対象外、創作の場合は理由も添える。
- 詳細レポート: 主・副分類、使った根拠と引用元、今回実行したカテゴリ別の評価軸を見せる。保存するテキストレポートにも分類を含める。
- 日本語・英語の両方に、カテゴリ名、保留・対象外の理由、専用質問、N/A の理由を用意する。
- サイトのレーダーチャートは通常チェックとレポートで維持する。本文のレーダーは、該当する基本項目と条件付き項目をカテゴリ内の4〜6軸にまとめ、各項目も一覧で示す。重要な副分類があれば別の本文レーダーを並べ、軸を一つの多角形に混ぜない。異なるカテゴリの多角形を同一尺度として比較させない。創作は「誤認防止」の確認として表示し、事実検証の点数とは呼ばない。一覧では本文レーダーを N/A と理由付きで表示する。

## 実装単位と受け入れ条件

1. 型・分類質問・ルーティングを実装し、同じ本文ならホストが変わっても分類と質問が変わらないことをテストする。
2. カテゴリ別の基本項目と条件付き項目、N/A、分類保留、長文の窓統合と切れ残りを実装する。既存のサイト安全性の質問と引用の追跡を維持する。
3. 通常チェック、詳細レポート、履歴、保存ファイル、日英表示を更新する。以前の記録も閲覧できるようにする。
4. 11分類と境界例、短文・混在・一覧・長文・日本語・英語を replay で検証する。カテゴリだけで安全性の判定が変わらないこと、他カテゴリの質問が送られないこと、通常画面にもレーダーが残ることを確認する。
5. 定義を変更するため、定義版を上げ、設定画面で**チェックリスト全体**の再承認を求める。分類表だけの承認を全質問の承認として扱わない。

この設計は [`judgement.md`](judgement.md) の「URL 固有の調整をしない」「意味判断は Jev、構造や入力の完全性はコード」「定義変更時は全件を再承認」の原則に従う。
