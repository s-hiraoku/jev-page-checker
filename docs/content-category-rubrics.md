# 本文分類別の評価項目案

状態: 設計案。質問文、Pass / Review / Alert / N/A の境界、実際の Jev 判定は未確定。

## 評価の原則

- サイト安全性（責任者、なりすまし、目的の明示、隠した勧誘）は分類に関係なく確認する。以下は**本文だけ**の評価項目である。
- 各項目は「そのページに読者が確認できる手掛かりがあるか」を問う。Jev が外部の事実を実地検証したかのようには表示しない。出典へのリンクの存在だけで、その出典の正しさを認定しない。
- 適用する主張がなければ N/A とし、Pass に数えない。必要な情報が本文から読めない場合は原則 Review、本文内に明確な矛盾・誤認を招く表示がある場合は Alert を検討する。カテゴリーだけを理由に Alert にしない。
- 項目数はカテゴリーの役割に合わせる。各質問は一つの意味判断に絞り、判定に関わる本文の文と、選択箇所を示す。
- 分類保留では専用項目を採点できないため本文を Review とする。重要な副分類がある場合は両方の項目を別々に実行・表示する。異なる分類の結果を数値で比較しない。
- 本文レーダーは項目数を制約にしない。全項目を一覧に出し、チャートにはカテゴリー内で関連する項目をまとめた4〜6軸を表示する。軸の判定は内包する項目の最も厳しい結果とし、個別の問題を平均で隠さない。創作・風刺だけの記事と一覧ページでは事実検証の本文レーダーは N/A と表示する。

以下の項目は、後掲の公開された一次資料を参考に、この製品の「ページ上で確認できる証拠」を見る目的に合わせて組み立てた**提案**である。引用元の団体がこのチェックリストを認証したという意味ではない。

## カテゴリー別の項目

1ページで実行する本文の基本確認は原則5項目とする。調査・検証は対象、測定、データ、分析を別々に確かめるため7項目、手順・ガイドは失敗時の対処と副作用を分けるため6項目、創作・風刺は事実検証を行わず誤認防止の4項目とする。重要な主張が現れた場合は後述の条件付き確認を追加する。下表の短い説明はユーザー向けの設計であり、Jev に送る質問文や判定境界は別途定義する。

| 分類 | 数 | 本文で確認する項目 | 主な参考資料 |
| --- | ---: | --- | --- |

| 当事者の発表・告知 | 5 | 1. **発表の主体と内容**: 誰が、自ら何を決定・実施・提供するのか分かるか。<br>2. **実績と予定**: 完了、計画、目標、予測を区別しているか。<br>3. **数値・性能の根拠**: 数値や効果の主張に、測定条件などの手掛かりがあるか。<br>4. **第三者に関する主張**: 外部組織、利用者、受益者の評価や同意を勝手に確定事実として扱わないか。<br>5. **適用範囲と条件**: 対象、開始時期、地域、利用条件や変更可能性が必要に応じて分かるか。 | [PRSA](https://www.prsa.org/professional-development/prsa-resources/ethics)、[FTC 広告FAQ](https://www.ftc.gov/business-guidance/resources/advertising-faqs-guide-small-business) |
| 解説・分析 | 5 | 1. **論点と用語**: 何を説明し、主要な言葉をどう使うか分かるか。<br>2. **資料の出所**: 中核となる事実や数値の元資料にたどれるか。<br>3. **資料の適合**: 資料の対象、時期、単位が説明したいことに合っているか。<br>4. **推論のつながり**: 資料から解釈・因果・結論への重要な飛躍がないか。<br>5. **比較と限界**: 比較条件、例外、不確実性を結論の強さに合わせて示しているか。 | [Full Fact](https://fullfact.org/about/how-we-fact-check/)、[Reuters](https://reutersagency.com/about/standards-values/) |

| 調査・検証 | 7 | 1. **問いと設計**: 何を調べ、観察・実験・比較をどう設計したか分かるか。<br>2. **対象の選び方**: 標本、期間、除外条件を追えるか。<br>3. **測定の定義**: 指標、単位、測定方法が分かるか。<br>4. **元データの出所**: データの収集・入手元を追えるか。公開できない場合は制約の説明があるか。<br>5. **分析手順**: 集計・比較・統計・判定方法が分かるか。<br>6. **結果の対応**: 主要な表や結論が提示した方法とデータに対応するか。<br>7. **不確実性と一般化**: 誤差、偏り、限界、結果を適用できる範囲を示すか。 | [EQUATOR / STROBE](https://www.equator-network.org/reporting-guidelines/strobe/)、[Center for Open Science](https://www.cos.io/initiatives/top-guidelines) |
| 手順・ガイド | 6 | 1. **目的と適用条件**: 完成状態、必要な環境・権限・版が分かるか。<br>2. **操作の再現性**: 手順の順序と分岐を追えるか。<br>3. **入力の具体性**: コマンド、値、対象物が必要な精度で示されているか。<br>4. **結果の確認**: 何を見れば成功や失敗を判断できるか。<br>5. **失敗時の対処**: 起こりやすい失敗と戻し方が必要に応じて分かるか。<br>6. **副作用・危険**: 削除、費用、権限変更、安全上の重要な影響を事前に示すか。 | [Google 手順ガイド](https://developers.google.com/style/procedures)、[Google prescriptive documentation](https://developers.google.com/style/prescriptive-documentation) |
| 体験・レビュー | 5 | 1. **使用の実体**: 筆者が何を、どの範囲で使ったか分かるか。<br>2. **評価条件**: 使用期間、環境、設定、比較条件が必要な範囲で分かるか。<br>3. **観察の具体性**: 評価の中心に、測定や実際の使用場面があるか。<br>4. **結果の節度**: 観察、好み、推測を区別し、個人の結果を一般的な成果にしないか。<br>5. **欠点と適用範囲**: 重要な制約や向かない用途を示すか。提供・報酬などの利害は共通のサイト安全性でも確認する。 | [FTC Endorsement Guides FAQ](https://www.ftc.gov/business-guidance/resources/ftcs-endorsement-guides-what-people-are-asking) |

| 創作・風刺 | 4（誤認防止） | 1. **創作の文脈**: タイトル、ジャンル、文体、配置から創作・風刺として読めるか。明示ラベルを必須にしない。<br>2. **現実の人物・出来事との境界**: 実在のものに触れる場合、創作中の描写と外部の事実主張を区別できるか。<br>3. **風刺・引用の境界**: 風刺対象や引用を、本人の事実発表と誤認させないか。<br>4. **現実の行動への誘導**: 作品外の効能・購入・投票などを促す重要な主張があれば、該当する副分類でも評価する。作品性や架空世界の事実は採点しない。 | [SPJ](https://www.spj.org/spj-code-of-ethics/)、[FTC native advertising](https://www.ftc.gov/business-guidance/resources/native-advertising-guide-businesses) |

創作・風刺の4項目は「信頼性の点数」ではなく、読者が現実の主張と混同しないための確認である。実在人物に触れない創作などでは該当しない項目を N/A にする。

## 重要な主張があるときの条件付き確認

基本の4〜7項目で重要な失敗を見落とさないよう、本文に次の特徴が**実際にある場合だけ**追加の問いを使う。URL、ホスト名、カテゴリ名だけでは起動しない。起動した問いと根拠も通常画面・レポートに表示する。該当する特徴が複数あれば必要な問いを追加し、Jev の入力枠や抽出範囲で読み切れないときは未確認を Review とする。

| 分類 | 追加確認を起動する内容 | 追加で確認すること |
| --- | --- | --- |
| 報道・事実報告 | 匿名の情報源、重大な申し立て、時系列や数値を根拠にした結論 | 匿名にする理由と独立した確認、当事者の応答、数値の基準と時点 |
| 当事者の発表・告知 | 将来の成果保証、他社比較、外部の推薦 | 前提条件、比較の方法、推薦者との関係 |
| 解説・分析 | 因果関係の断定、予測、異なる集団・期間の比較 | 別の説明、予測の前提、比較可能性 |
| 意見・提案 | 数値で示す効果、特定の政策・行動による因果効果の主張 | 推計の前提、代替案、未測定の影響 |
| 調査・検証 | 統計的な差、因果効果、非公開データや特殊な除外 | 統計の前提、交絡への対応、非公開・除外の理由 |
| 手順・ガイド | 削除、支払い、権限変更、健康や安全に関わる操作 | 事前確認、危険の条件、戻し方や専門家による確認の要否 |
| 体験・レビュー | 提供品・報酬・紹介料、ベンチマークや大幅な性能差 | 利害の明示、測定方法、結果の再現範囲 |
| 販売・勧誘 | 継続課金、健康・金銭上の効果、限定期間や残数、推薦文 | 解約や総負担、主張に見合う証拠、期限・残数の根拠、推薦者との関係 |
| 資料・参照 | 廃止予定、複数の版・単位・適用地域 | 版ごとの差分、変換・移行条件、旧情報の扱い |
| 投稿・議論 | 相反する回答、承認済みの古い回答、版に依存する解決策 | 未解決の論点、承認と正しさの区別、現行環境への適用範囲 |
| 創作・風刺 | 実在人物・事件への言及、作品外の購入・投票・効能への誘導 | 創作上の描写と現実の主張の境界。現実の重要な主張は対応する副分類でも確認 |

### Pass を表示するための条件

分類が確定し、本文が読み切れており、該当する基本項目と条件付き項目をすべて実施したときだけ本文レーンを Pass にできる。適用不能な項目は N/A として数えず、適用項目が一つもない場合は本文も N/A とする。重要な条件が本文から読めない場合は Review と理由を出す。分類保留、重要な副分類の未評価、抽出漏れ、Jev の入力超過があれば Pass にしない。サイト安全性の Pass は本文の Pass を代用しない。

項目が多い分類ほど Alert が出やすくなるため、分類をまたいだ総合点や順位は作らない。各項目の結果と引用文を見せ、本文レーンは最も厳しい**適用項目**の判定を示す。条件付き項目が起動した理由も保存する。

## 判定の実装前に決めること

1. 各項目の原子性を確認し、必要なら分割する。上の説明はユーザー向けであり、このまま Jev に長い複合質問として投げない。
2. 各項目について、適用条件と N/A、Pass、Review、Alert の基準を具体例付きで定める。項目数が多い分類が不利にならないよう、全項目の最悪値だけで横断比較しない。
3. ページから取り出せる本文・表・脚注・価格表示・発言者情報の範囲を確認する。抽出できないために判定できない場合は Review と説明する。
4. 日英で同じ意味の表示名と説明を用意し、実在ページの例と境界例で分類、基本項目、条件付き項目の起動、N/A、根拠文の対応を検証する。異なるカテゴリが同じサイトにある例や、販売を報道に見せた例も含める。個別 URL に合わせて基準を動かさない。
5. 人が確認した例で、カテゴリ別の誤分類、重要な見落としによる誤った Pass、N/A の誤用、引用文の無関係さを別々に記録して改善する。項目数の多さだけを成功指標にしない。
6. 定義変更時は [`judgement.md`](judgement.md) に従い、条件付き項目も含めて質問リスト全体を再承認する。

参考にした基準は、それぞれの文脈向けの公開資料である。特に [STROBE](https://www.equator-network.org/reporting-guidelines/strobe/) は報告の透明性を助けるもので、研究の質そのものを測る道具ではない。本製品も「ページが評価に必要な材料を見せているか」を示し、実世界での正誤や方法の妥当性を保証しない。
